留学生政策雷达

面向在美留学生的官方政策变动监控与推送 · 进行中 · 2026.10 起 · 3 人团队，产品负责人兼开发

只盯官方页面的变化：美国签证与留学生身份政策一有官方变动，系统自动比对、生成中文摘要、附原文链接和状态标签，推送给订阅的中国留学生。不做政策问答，不做法律建议。

13白名单官方信源
42已通过的自动化测试
≤60 分钟发布到推送的时效目标
背景三条铁律范围取舍流程评测体系分歧与决策规则进度

背景

为什么只盯变化：问政策 ChatGPT 能答，但"今天有没有变、变在哪、生效了没"需要有人持续盯着十几个官方页面并做比对，这件事聊天窗口做不了，也没有人愿意天天做。

政策变动有多频繁？用 Federal Register 官方接口检索含 "F-1 students" 的文件，近期命中 90 条，最新三条是：

日期类型标题
2026-10-08拟议规则Optional Practical Training Fees
2026-09-11拟议规则Eliminating the Discretionary 60-Day Grace Period
2026-08-10最终规则9-11 Response and Biometric Entry-Exit Fee for H-1B and L-1 Visas

每一条都会在留学生群里引发一轮截图转发和恐慌，而"拟议"和"生效"的区别在转发中通常丢失。学校国际办公室的邮件可靠但常滞后一到三天，且只覆盖与学校相关的内容；官方信息是英文、分散在 USCIS、国务院、DHS、使馆、学校等十几处。

三条铁律

  1. 只用官方信源白名单，白名单变更要有记录。遇到反爬，例如国务院签证页面对脚本返回 403，不绕过，改为人工信源。
  2. 每条推送必须附原文链接和原文引用片段，引用由代码校验确实存在于原文。
  3. 不解读法律后果，不给个案建议。"对我有什么影响"只回答到"涉及人群、当前状态、关键日期"。

范围取舍

MVP 必做

编号需求说明
M1信源监控白名单 8 到 13 个，RSS 与 API 优先，网页抓取兜底
M2变化检测新条目加页面关键区域变更，带去噪规则
M3相关性与分类相关与否；人群、主题、状态、影响等级
M4中文摘要卡三句话加原文引用加链接加状态标签
M5订阅与推送邮件、网页时间线、RSS 输出；按人群和主题订阅
M6反馈每条"有用、与我无关、有错误"一键反馈
M7高影响复核窗口高影响条目发布前 15 分钟人工复核，过期自动放行

明确不做及理由

不做理由
政策问答聊天ChatGPT 能做；问答极易越界成法律建议
法律建议、个案解读合规风险，且不是差异点
监控群聊和小道消息信源不可控，正是谣言的来源
多国政策先验证美国这一条线的模式
小程序、AppMVP 用网页加邮件验证渠道，再决定投入

流程

定时触发（RSS/API 每 30 分钟，网页每 2 小时）
→ 拉取信源 → 保存原始快照 → 规范化为条目或段落
→ 与上次快照比对 → 候选变化 → 去噪规则
→ 模型任务 1：相关性与分类（结构化输出）
   ├─ 不相关 → 归档（保留供评测）
   └─ 相关 → 模型任务 2：生成摘要卡（结构化输出）
→ 代码校验：引用片段 ⊂ 原文、日期与数字 ⊂ 原文、字段完整
   ├─ 失败 → 重试一次 → 再失败进人工队列
   └─ 通过 → 影响等级
        ├─ 高 → 15 分钟人工复核窗口 → 放行 / 修改 / 拦截
        └─ 中、低 → 直接发布
→ 发布：写入时间线与 RSS；按订阅推送邮件
→ 用户反馈 → 回流评测集与迭代
原则与 ProteinWallet 一脉相承：模型只做判相关和写摘要两件事，检测、去噪、日期抽取、引用校验、发布决策全部由代码与规则完成。

评测体系

评测集来源规模
历史变动集Federal Register、USCIS、使馆公告，回溯一年正样本 50 条、负样本 50 条
摘要评测集对正样本生成摘要卡30 条，双人标注
页面去噪集5 个页面型信源连续 7 天快照全部变化人工标注
指标定义上线标准
变化检出率正样本被检测且判为相关的比例≥ 90%
误报率已推送条目中被标注为不相关或无意义的比例≤ 10%
分类准确率人群、主题、状态标签与标注一致≥ 85%
摘要忠实度有依据的事实句占比≥ 95%
幻觉率含无依据事实句的条目占比≤ 3%
时效官方发布到推送的中位延迟≤ 60 分钟

双人独立标注，不一致由第三人仲裁；每轮 prompt 改动跑评测集并记录指标变化。评测阶段横向对比 Claude、GPT、DeepSeek、Qwen 的忠实度与成本，产出选型结论。

预判的分歧与决策规则

分歧两边决策规则
小道消息推不推速度 vs 可靠MVP 只推官方；v2 评估"待官方确认"层，前提是误报率已稳定 ≤ 10%
即时推送 vs 每日汇总时效 vs 打扰按影响等级分流，高和中即时、低汇总；上线两周后用退订率和打开率复核
要不要写"对你的影响"用户想要 vs 法律风险只到人群、状态、日期；若访谈显示强需求，引入学校国际办公室的建议链接，不自写建议
高影响要不要人工复核自动化 vs 出错代价15 分钟窗口，过期自动放行；一致率连续两周 ≥ 95% 后缩短窗口
